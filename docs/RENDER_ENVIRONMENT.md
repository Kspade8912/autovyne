# Render Environment Setup

The `render.yaml` Blueprint declares the environment-variable names, but secret values must only be entered in Render. Never commit API keys to GitHub.

## Required Before Deploying

- `DATABASE_URL`: Supabase Postgres Session Pooler connection string. Without it, public pages stay online in degraded mode while database-backed lead capture remains unavailable.
- `OPENAI_API_KEY`: OpenAI project API key for AI-agent features.
- `HUBSPOT_ACCESS_TOKEN`: HubSpot private app token with `crm.objects.contacts.write`.
- `N8N_WEBHOOK_URL`: Production webhook URL from the active n8n workflow.
- `N8N_WEBHOOK_SECRET`: A long random value configured as the n8n webhook header-auth value.

## Generated By Render

- `COOKIE_SECRET`
- `ADMIN_API_KEY`
- `ANALYTICS_IP_SALT`

Render generates these values automatically from the Blueprint.

## Optional Integrations

- `POLSIA_API_KEY`: prospect auto-reply email integration.
- `POLSIA_ANALYTICS_SLUG`: Polsia analytics beacon.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `LEAD_NOTIFY_EMAIL`: internal lead notifications.

## Adding More AI Agents

Each outside provider should get a separate private key, for example:

- Calling provider: `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, or the selected provider's equivalent.
- CRM: provider-specific private token.
- Lead enrichment: provider-specific private token.

Add the variable name to `render.yaml` with `sync: false`, then enter its value in the Render Dashboard. Do not add the value to `.env.example`, source code, commits, messages, or screenshots.

## Provider Setup

### Supabase

1. Create or select a Supabase project.
2. In **Connect**, copy the Session Pooler connection string.
3. Enter it as `DATABASE_URL` in Render.
4. Deploy once. `npm run build` creates the required tables and enables RLS.

The server connects directly to Postgres. No Supabase service-role key is exposed or required.

### OpenAI

1. Create a project API key.
2. Enter it as `OPENAI_API_KEY` in Render.
3. Keep `OPENAI_MODEL=gpt-5.4-mini` unless intentionally changing the qualification model.

OpenAI generates a factual lead qualification brief after each saved lead. Failure never blocks the form response.

### HubSpot

1. Create a HubSpot private app.
2. Grant `crm.objects.contacts.write`.
3. Enter its token as `HUBSPOT_ACCESS_TOKEN` in Render.

Leads with email addresses are upserted into HubSpot using email as the unique identifier.

### n8n

1. Create a workflow beginning with a Webhook node using `POST`.
2. Enable Header Auth with header name `X-Autovyne-Secret`.
3. Set the header value to the same random value used for `N8N_WEBHOOK_SECRET`.
4. Activate the workflow and enter its production URL as `N8N_WEBHOOK_URL` in Render.

The webhook receives `event`, `sent_at`, `lead`, and the OpenAI `qualification` brief.

## Verification

Call `GET /api/integrations/status` with:

`Authorization: Bearer <ADMIN_API_KEY>`

It reports which integrations are configured and whether Supabase is reachable without exposing secrets.
